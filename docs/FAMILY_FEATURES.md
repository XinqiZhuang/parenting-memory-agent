# 家庭功能升级：安装、使用与部署

本包针对已升级到 V2、全量 155 项测试通过的 parenting-memory-agent 项目。沿用同一份 baby.json 和已配置的 DeepSeek/飞书账号。新增功能的真实 API 和服务器验收需在你自己的账号下完成。

## 1. 本地安装

先在飞书、网页、定时服务终端按 Ctrl+C，停止旧进程。解压升级包到项目根目录，得到 `parenting-agent-family-upgrade` 文件夹。

在项目根目录的 PowerShell 逐行运行（不需要激活虚拟环境）：

```powershell
.\.venv\Scripts\python.exe .\parenting-agent-family-upgrade\apply_upgrade.py --project .
.\.venv\Scripts\python.exe .\parenting-agent-family-upgrade\apply_upgrade.py --project . --apply
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe .\configure_features.py
.\.venv\Scripts\python.exe .\verify_features.py
```

更新器会校验包内文件、备份被替换的代码，并保留原 `.env`、宝宝数据、照片和家庭成员信息。新配置由本机向导写入，不覆盖原 DeepSeek Key。代码备份在 `upgrade-backups`；配置备份在被 Git 忽略的数据目录下。

在三个终端分别启动：

```powershell
.\.venv\Scripts\python.exe .\feishu_bot.py
```

```powershell
.\.venv\Scripts\python.exe -m streamlit run streamlit_app.py --server.address=127.0.0.1
```

```powershell
.\.venv\Scripts\python.exe .\run_scheduler.py
```

网页打开 http://localhost:8501 。必须在同一个项目目录运行；程序都读取 `PARENTING_DATA_DIR`。需要持续运行时再按第7节部署到服务器。

## 2. 网页档案总览

左侧选“档案总览”：

- 时间线、分类、关键词、日期范围筛选、缺日期记录单列。
- 查看照片、表格和每日记录汇总；下载筛选后的 CSV。
- 查看最近100条实际数据操作；完整审计仍保留在档案数据中。
- 飞书确认保存的内容和网页共用档案，点击“刷新档案”读取最新数据。
- 记录数不等于真实事件次数；同名但不同分类的历史记录不会擅自合并。

## 3. 飞书保存照片

只处理允许列表内的群/成员。群里需要 @ 机器人，`FEISHU_BOT_NAME` 要与实际显示名称完全一致；也可配置 `FEISHU_BOT_OPEN_ID` 精确匹配。

**推荐发送方式：**在同一条富文本消息中 @ 机器人并附上照片；或者私聊机器人发照片。纯图片群消息是否送达取决于飞书事件权限，代码不能绕过平台权限。

1. 可以先发 `@育儿助手Agent 上传照片`。
2. 发1～8张静态 JPG / PNG / WEBP，每张最多10MB、2400万像素。
3. 机器人显示收到照片后，发送真实描述，例如：

   `@育儿助手Agent 照片描述 这是宝宝今天在客厅玩套杯的照片`

   或使用无需模型理解的明确格式：

   `@育儿助手Agent 照片信息 标题=套杯游戏；日期=2026-09-20；描述=在客厅和爸爸玩套杯`

   示例日期请换成真实日期；不知道可写 `日期=未知`。上传日期不会自动当成发生日期。
4. 核对预览，再发送 `@育儿助手Agent 确认`。
5. 网页“照片回忆”“档案总览”刷新后即可看到。

可连续上传同一事件的多张照片，草稿30分钟内有效；生成保存预览后确认有效期20分钟。回复“取消”不会新增档案。取消或过期后的临时文件仍在私有数据目录内，可使用 `cleanup_photo_cache.py` 预览并清理超过7天且未被档案/审计引用的临时图。软删除照片记录仍保留原图，便于撤销。

**飞书权限核对：**沿用接收消息事件 `im.message.receive_v1`、机器人发消息权限。图片下载需要平台接口允许获取消息资源；根据开发平台“获取消息中的资源文件”接口列出的权限配置并发布应用新版本。若希望收到未@机器人的单独群图片，还需要相应群消息接收权限；代码只在该发送者开启上传窗口后处理未@的纯图片，普通群聊天会忽略。

官方接口参考：[获取消息资源](https://open.feishu.cn/document/server-docs/im-v1/message-resource/get)、[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)。SDK调用结构已按项目安装的 lark-oapi 1.7.3 核对，权限和事件实际送达需在自己的飞书租户验证。

## 4. 图片识别

现有文本模型调用保留不变。图片识别使用一个独立、支持图片输入的 OpenAI 兼容 Chat Completions 接口。

配置向导会询问：

```dotenv
VISION_API_KEY=你的图片模型API密钥
VISION_BASE_URL=控制台给出的OpenAI兼容接口地址
VISION_MODEL=该接口支持图片输入的模型ID
```

不要把聊天网页网址填到 BASE_URL；也不要自动把文本模型名称当作视觉模型。可使用已拥有的兼容视觉服务。例如阿里云百炼的[视觉理解官方文档](https://help.aliyun.com/zh/model-studio/vision)提供了图片输入示例；接口地域、业务空间和模型名称以自己控制台为准，本包未代开账号或代购额度。

v3.0.2：通过阿里云官方域名调用 `qwen3.8-max`、`qwen3.8-flash`（含其快照版本）时，照片描述会使用非思考模式和 JSON 输出。模型名称保持不变；这是图片描述任务的调用参数，不影响 DeepSeek 的文本处理。其他服务仍使用原有通用调用参数。

- 飞书收到图片后发送 `识别照片`（群里仍需@机器人）。
- 网页先选图，勾选发送给图片模型，再点击“识别照片，生成草稿”。
- 每次最多识别4张，会发送去除 EXIF 的缩小副本。原图只保存在你配置的数据目录。
- 模型只生成事件标题和可见内容描述，不自动推断姓名、日期、月龄、第一次发生、能力掌握程度或诊断。
- 识别有可能出错。用户核对并补充日期后，再确认保存。未配置图片接口或调用失败时仍可以手动填写、保存原图。

可选的真实接口检查（会消耗少量图片模型额度）：

```powershell
.\.venv\Scripts\python.exe .\verify_features.py --live-vision
```

此检查只发送自动生成的白底橙色圆形图，不读取真实宝宝照片。成功代表接口与JSON返回链路可用，不代表宝宝照片识别准确率已验证。

## 5. 每日总结和早教推送

网页左侧“每日推送”：

1. 填入群 chat_id，该群必须在 `FEISHU_ALLOWED_CHAT_IDS` 中。
2. 设置时区，默认 `Asia/Shanghai`。
3. 勾选每日总结/早教知识，分别设置发送时间；默认建议21:00、09:00。
4. 点击“保存推送设置”；单独启动 `run_scheduler.py`。
5. 网页显示服务心跳和最近发送状态。

网页默认日期采用这里的时区；现有V2自然语言中的“今天/昨天”按中国时区解析。默认配置二者一致；若改为其他时区，记录时请写明实际日期。

日报按“事件日期”汇总已确认、未删除的六类档案，计算已记录的奶量与活动时长，不编造缺失事件、不把“没记录”说成“没发生”。默认汇总发送时当天已有记录，因此当天后续新增内容不会自动补发；如果要包含整天，可以开启“总结前一天”，在次日00:30发送。

早教首版为知识库中7条通用亲子养育摘录按日轮换；每条标明PDF文件和页码，发送前核对摘录与原文。它不是无限生成课程，也不依据少量记录判断宝宝发展水平。PDF缺失或文本校验失败时本次发送停止并记录错误。

定时服务每20秒检查一次，默认允许错过时点后2小时内补发，当天同一类型只发一次。超出窗口不追发旧日报。成功记录持久化，重启不重复发送；多个同机进程抢同一个任务时只允许一个进入发送。飞书创建消息带固定 UUID，但跨网络无法承诺数学意义上的绝对仅发送一次。

网络超时或发送进程崩溃可能导致“送达不确定”：系统保留记录、不自动重发。先到飞书核对，再在网页人工处理。明确被飞书拒绝的消息最多自动尝试3次，每次至少间隔5分钟。暂停配置会阻止尚未进入发送阶段的任务；已经发出的网络请求无法撤回。

**快速验收：**先点击“仅预览，不发送”；再把一个任务的时间设为当前时区2分钟后并开启。观察群消息和网页状态，然后重启定时进程，确认不会重复发送。验收后改回正式时间。

## 6. 网页密码

配置 `WEB_PASSWORD` 后网页需要登录。`APP_ENV=production` 要求密码至少16位。

这是单家庭共用密码，不是完整的多租户/细粒度角色系统。家庭成员可以看档案和调整推送；如需公共访问，必须使用HTTPS。公共作品集网站只放经过处理的截图，不要直接嵌入真实家庭档案。

## 7. 部署到一台持续在线的服务器

本包提供 Dockerfile、compose.yaml 和可选 Caddy HTTPS 配置，不绑定 Railway。可以使用你已有的支持 Docker Compose 的 Linux 服务器。没有服务器账号时，本地三个进程仍可完整联调；电脑休眠/断网/关机后无法实时接收或推送。

**迁移前：停止本地三个程序。保留本地数据备份。不要同时在电脑和服务器各跑一套不同的档案。**

把已更新项目上传到服务器工作目录，并将本地实际数据目录中的完整内容（baby.json、uploads、家庭成员、状态文件等）复制到服务器项目下的 `runtime-data/`。不要只复制代码，否则服务器会读取示例档案。

在服务器项目目录创建 `.env`，填入已有密钥及至少16位网页密码，再执行：

```bash
chmod 600 .env
sudo mkdir -p runtime-data
sudo chown -R 10001:10001 runtime-data
docker compose build web
docker compose up -d web bot scheduler
docker compose ps
docker compose logs --tail 60 bot scheduler
```

三个服务都挂载同一个 `runtime-data` 到 `/data`；容器以UID10001运行。不要把各服务分到不同服务器，也不要将JSON放到多个实例共享的网络磁盘。

先用SSH隧道访问网页，不需要域名。在自己电脑的PowerShell另开终端：

```powershell
ssh -L 8501:127.0.0.1:8501 你的服务器用户名@服务器地址
```

保持这个终端打开，浏览器访问 http://localhost:8501 并输入家庭密码。服务器默认不对公网直接开放8501。

若需要家人直接通过网址访问：给家庭子域名配置DNS到该服务器，在服务器`.env`加入 `FAMILY_DOMAIN=你的家庭子域名`，放行80/443端口，然后执行：

```bash
docker compose --profile public up -d gateway
```

Caddy负责HTTPS转发；首次证书签发需要正确DNS和外网连通。部署参数参考[Caddy官方反向代理说明](https://caddyserver.com/docs/quick-starts/reverse-proxy)。本次交付环境没有Docker守护进程，未执行真实容器构建或服务器发布；请按本节实际验收，不把配置文件完成当成上线成功。

定期备份 `runtime-data`；备份前停止三个写入进程，再复制完整目录，完成后重新启动。已有相对/旧Windows形式的 `data/uploads/...` 引用会在新数据目录下解析，不会读取目录外文件。

## 8. 本次验证范围

见 `docs/FAMILY_VERIFICATION.md`。自动化测试使用临时数据和模拟外部接口，不发送真实照片/群消息。真实图片模型、飞书权限、服务器运行和至少两个自然日的定时执行需要你本机/部署后验收。

建议按四个场景一次验收：

- 飞书上传照片 → 描述/识别 → 预览 → 确认 → 网页可见。
- 两位家庭成员分别上传，不能互相确认草稿。
- 总览按日期筛选，日报奶量等与原始记录一致。
- 设置2分钟后的推送，收到一次；重启不重复，暂停后不发送。
